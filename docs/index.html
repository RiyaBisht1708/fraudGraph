FraudGraph

Graph-Based Financial Fraud Detection

A transaction is more than a row. FraudGraph models the relationships between transactions, cards, merchants, and devices as a heterogeneous graph—giving fraud analysis a way to reason about connected entities and shared behavioral context.

01 · Motivation

Fraud rarely happens in isolation.

Row-by-row signals can miss the shared entities and repeated connections that make a series of transactions meaningful.

THE LIMITATION

Transactions viewed one at a time

A transaction-level model evaluates the features in one row. Connections—such as a card appearing across transactions or an entity recurring across activity—are not explicit in that view.

THE GRAPH VIEW

Entities become context

A heterogeneous graph represents transactions alongside cards, merchants, and devices. Message passing can use linked neighborhood structure as part of the fraud signal, rather than treating each event as disconnected.

06 / EXPLAIN

Explainability

Graph construction

Transactions connect to card, merchant, and device entities, with temporal velocity-cluster edges. PyTorch Geometric represents the heterogeneous graph; NetworkX is a graph-prototyping reference, not a dependency in the current implementation.

Modeling & baselines

GraphSAGE models neighborhood information; hybrid GNN and XGBoost baselines are compared on a temporally held-out test set. PureSAGE is the selected inference architecture.

Local serving path

FastAPI receives scoring requests, while Redis maintains rolling transaction context and Kafka carries stream events. The inference service has been tested locally, not deployed as a public API.

Offline graph construction and training artifacts are separate from the local serving stack. This research prototype is not represented as a production deployment.

06 · Research & engineering

A disciplined path through the problem.

Experiments are organized around temporal evaluation, relational representation, model comparison, and inspectable outputs.

01

Temporal split

Training, validation, and test are separated by timeline (70/10/20). Validation informs model selection; test results are reported separately.

02

Heterogeneous graph

Transactions, cards, merchants, and devices are represented as node types. Typed links include entity associations and transaction velocity clusters.

03

GraphSAGE experiments

PureSAGE and a hybrid GraphSAGE/attention model explore message passing across edge types, alongside a strong XGBoost baseline.

04

Model comparison

ROC-AUC, Average Precision, and Precision at 10% Recall provide complementary views of held-out test performance.

05

Evidence-based explanations

The serving code includes an explanation layer that reports graph-grounded reasons; this site makes no claim that an online public explainer is available.

06

Scope & limitations

A research implementation and local serving test are not equivalent to a production system or a publicly accessible inference endpoint.
